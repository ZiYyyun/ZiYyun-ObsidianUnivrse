AC79 官方 SDK 已经提供语音前端和关键词唤醒接口，但不是一个统一的“语音唤醒 API”，而是“音频前处理 + 某套唤醒算法库”的组合。

官方仓库目前包含：

- `jlkws`：杰理关键词唤醒
- `aisp`：思必驰方案
- `roobo`：ROOBO 打断唤醒
- `wanson`：华镇唤醒
- 音频前端：AEC、NLP、ANS、VAD、降噪等

核心调用流程如下：

```c
int model = 0;
int model_size;
int private_heap_size;
int share_heap_size;
void *kws;

jl_far_kws_model_get_heap_size(
    model,
    &model_size,
    &private_heap_size,
    &share_heap_size
);

void *private_heap = zalloc(private_heap_size);
void *share_heap   = zalloc(share_heap_size);

kws = jl_far_kws_model_init(
    model,
    private_heap,
    private_heap_size,
    share_heap,
    share_heap_size,
    model_size,
    confidence,
    0
);
```

然后连续送入单声道 PCM：
```c
short pcm[160];

/* 16 kHz、16 bit、单声道，每次160点，即10 ms */
int ret = jl_far_kws_model_process(
    kws,
    model,
    (char *)pcm,
    sizeof(pcm)
);

if (ret > 1) {
    /* ret 是唤醒词或命令词编号 */
    handle_keyword(ret);
    jl_far_kws_model_reset(kws);
}
```

退出时：

```c
jl_far_kws_model_free(kws);
free(private_heap);
free(share_heap);
```

官方示例还封装了更容易使用的控制接口：

```c
int  aisp_open(u16 sample_rate);
void aisp_suspend(void);
void aisp_resume(void);
void aisp_close(void);
```

一般在音频硬件初始化完成后启动：

```c
aisp_open(16000);
```

这段封装内部已经完成：

```c
MIC/PLNK/IIS
    -> audio_server 编码采集
    -> AEC/NLP/ANS 前处理
    -> PCM 环形缓冲
    -> jl_far_kws_model_process()
    -> 返回命令词编号
```

工程配置至少需要关注这些宏：

```c
CONFIG_ASR_ALGORITHM
JLKWS_ALGORITHM

CONFIG_AISP_MIC0_ADC_CHANNEL
CONFIG_AISP_MIC_ADC_GAIN

CONFIG_AEC_ENC_ENABLE
CONFIG_AEC_USE_SMS_TDE
CONFIG_AEC_USE_PLAY_MUSIC_ENABLE
```

前端声学部分通过 `audio_server` 配置。例如官方代码使用：

```c
struct aec_s_attr aec_param = {0};

aec_param.EnableBit = AEC_EN | NLP_EN | ANS_EN;

req.enc.aec_enable  = 1;
req.enc.aec_attr    = &aec_param;
req.enc.sample_rate = 16000;
req.enc.channel     = 1;
req.enc.format      = "pcm";

server_request(audio_server, AUDIO_REQ_ENC, &req);
```

几个关键注意点：

1. 官方 JLKWS 示例默认是 `16 kHz / 16 bit / 单声道 / 每帧160点`。
2. `confidence[]` 是每个词对应的阈值，越高越不容易误唤醒，但漏唤醒会增加。
3. 唤醒词通常固化在模型或静态库中，不能简单把 `"小杰小杰"` 改成其他字符串。自定义唤醒词一般需要杰理或算法供应商重新生成模型、授权文件或静态库。
4. `aisp_open()` 只是官方示例里的应用层封装，不同 SDK 版本可能没有公共头文件，必要时自行声明或抽成自己的 `asr_service.h`。
5. 打断播放场景必须给 AEC 提供正确的 DAC 参考信号，否则音箱播放内容很容易造成自唤醒。

最适合的起点是直接把 `apps/common/asr/jlkws/jlkws.c` 接入你的工程，先保持默认唤醒词跑通，再调整 MIC 增益、AEC 参数和 `confidence[]`。
