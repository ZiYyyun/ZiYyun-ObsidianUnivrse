#理论/嵌入式/STM32 

在系统或电源复位以后，微控制器处于运行状态。当CPU不需继续运行时，可以利用多种低功耗模式来节省功耗，例如等待某个外部事件时。用户需要根据最低电源消耗、最快速启动时间和可用的唤醒源等条件，选定一个最佳的低功耗模式。

>低功耗不是“睡觉”，而是**系统不同层级的断电**并只保留需要工作的地方：
	尽可能地关闭：`CPU` `主时钟` `PLL` `Flash` `外设时钟`

| 场景     | 需求        |
| ------ | --------- |
| 延时中断   | CPU暂停即可   |
| 等中断    | CPU停，外设继续 |
| 电池设备待机 | SRAM保留    |
| 几个月待机  | SRAM也不需要  |


---

> [!NOTE] 低功耗模式分类
> STM32总共有三种低功耗模式：
> ● **睡眠模式**(Cortex™-M3内核停止，所有外设包括Cortex-M3核心的外设，如NVIC、系统时钟(SysTick)等仍在运行) 
> ● **停止模式**(所有的时钟都已停止) 
> ● **待机模式**(1.8V电源关闭) 
> *此外，在运行模式下，可以通过以下方式中的一种降低功耗：* 
> *● 降低系统时钟* 
> *● 关闭APB和AHB总线上未被使用的外设时钟。*

### STM32低功耗模式分类
| 模式             | CPU  | 主时钟 | SRAM | 唤醒后  |
| -------------- | ---- | --- | ---- | ---- |
| Sleep          | 停止   | 保留  | 保留   | 继续执行 |
| Stop           | 停止   | 关闭  | 保留   | 继续执行 |
| Standby        | 断电   | 关闭  | 丢失   | 系统复位 |
| Shutdown（部分型号） | 几乎全断 | 关闭  | 丢失   | 系统复位 |

### 低功耗的原理
在了解低功耗原理之前，先回顾一下STM32的时钟源：

| 时钟  | 说明          |
| --- | ----------- |
| HSI | 内部高速 RC     |
| HSE | 外部高速晶振      |
| PLL | 倍频器         |
| MSI | 多级内部时钟（L系列） |
| LSI | 低速内部        |
| LSE | 32.768kHz晶振 |
因为STM32的时钟在不停地产生频率，所以功耗的最大变量就是时钟

                              $P ≈ C × V² × f$

%% C:电容     V:电压    f:频率 %%

所以当我们关闭CPU或HSE时，功耗就会暴跌。所以，stop模式的功耗远低于sleep模式的原因是，**stop模式相比之下多关闭掉了时钟**。


### sleep模式
>**核心定义：只关 CPU 内核，其他所有硬件全活**

- 断电范围：仅 Cortex-M3 内核停止运行
- 保留范围：所有时钟（HSI/HSE/PLL）、所有外设、SRAM、所有寄存器状态全部保留
- 唤醒时间：**极快（微秒级）**，几乎无延迟
#### 唤醒源
**任何中断 / 事件都能唤醒**
- 所有外设中断（UART、SPI、ADC、TIM、DMA 等）
- 外部中断 EXTI
- SysTick 滴答定时器中断
#### 进入方式
[[todo]]
``` c
__WFI();  // Wait For Interrupt：等待中断唤醒（最常用）
__WFE();  // Wait For Event：等待事件唤醒
```

> [!WARNING] 必踩坑
> 
> 如果开启了 SysTick 定时器，它会每 1ms 产生一次中断，会立刻把 CPU 从睡眠模式唤醒！
> 
> 进入睡眠前如果不需要 SysTick，一定要先关闭：`SysTick->CTRL &= ~SysTick_CTRL_ENABLE_Msk;`
#### 典型场景
- CPU 没事干，等外设干活：比如 DMA 正在搬数据、ADC 正在采样、UART 正在接收
- 低延迟响应需求：需要中断来了立刻处理
- 功耗要求不高，但想解放 CPU 的场景

### stop模式
>**核心定义：所有高频时钟全关，只保留低速时钟和 SRAM**
- 断电范围：HSI、HSE、PLL 全部关闭，所有依赖这些时钟的外设全部停止
- 保留范围：SRAM、所有寄存器状态、低速时钟（LSI/LSE）
- 唤醒时间：**毫秒级**，比睡眠慢，因为需要重新启动高频时钟
#### 唤醒源
**只有能在无高频时钟下工作的模块能唤醒**
- 外部中断 EXTI（所有 GPIO 引脚）
- RTC 闹钟 / 唤醒事件
- IWDG 独立看门狗复位（如果开启了）
#### 进入方式
[[todo]]
```c
// 配置PWR_CR寄存器，进入停止模式
PWR->CR |= PWR_CR_PDDS;  // 0=停止模式，1=待机模式
PWR->CR |= PWR_CR_LPDS;  // 开启深度停止（可选，功耗更低，唤醒稍慢）
__WFI();
```

> [!WARNING] 最大的坑！90% 的人都会踩
> 
> 唤醒后，**所有高频时钟都处于关闭状态**，系统会默认使用内部 8MHz 的 HSI 时钟运行
> 
> 必须立刻重新调用你的`SystemInit()`函数，重新配置 PLL 和系统时钟，否则程序会以 8MHz 跑飞

> [!NOTE] 两种停止模式区别
> 
> - 普通停止：Flash 保持供电，唤醒更快
> - 深度停止：Flash 也掉电，功耗降低约 30%，唤醒延迟增加几毫秒
#### 典型场景
- 几秒钟到几分钟的短时间待机
- 需要保留 SRAM 里的变量和程序状态
- 只需要按键或 RTC 闹钟唤醒的场景
- 电池供电设备的常规待机模式
### standby模式
>**核心定义：除了备份域，整个芯片几乎全断电**
- 断电范围：1.8V 核心电源域关闭，CPU、所有外设、SRAM、所有寄存器全部断电
- 保留范围：仅备份域（Backup Domain）和待机电路
- 备份域包含：RTC、备份寄存器（BKP，共 20 个字节）、LSE 时钟
- 唤醒时间：**和上电复位一样慢（几十毫秒）**
#### 唤醒源
**只有 3 种，没有其他任何方式**
1. WKUP 引脚（PA0）上升沿
2. RTC 闹钟事件
3. NRST 外部复位引脚
#### 进入方式

```c
// 清除唤醒标志，否则会立刻唤醒
PWR->CR |= PWR_CR_CWUF;
PWR->CR |= PWR_CR_CSBF;

// 配置进入待机模式
PWR->CR |= PWR_CR_PDDS;  // 1=待机模式
__WFI();
```

> [!NOTE] 关键特性
> 
> 唤醒后**相当于一次完整的系统复位**，程序会从`main()`函数重新开始执行
> 
> 可以通过读取`PWR->CSR`寄存器的`SBF`位，判断是上电复位还是待机唤醒：
> 
> c
> 
> 运行
> 
> ```
> if(PWR->CSR & PWR_CSR_SBF) {
>     // 是从待机模式唤醒的
>     PWR->CR |= PWR_CR_CSBF; // 清除标志
> }
> ```

> [!WARNING] 数据保留
> 
> SRAM 里的所有数据都会丢失！如果需要保存少量关键数据，只能存在备份寄存器 BKP 里
> 
> 使用备份寄存器前需要先开启备份域时钟：`RCC->APB1ENR |= RCC_APB1ENR_PWREN | RCC_APB1ENR_BKPEN;`
#### 典型场景
- 几分钟到几个月的长时间待机
- 对功耗要求极高的电池设备（比如纽扣电池供电）
- 不需要保留程序状态，唤醒后重新初始化即可的场景
